# EGM Drift Report — vanguard.md vs `vanguard/` implementation

Date: 2026-11-03 · Design: `docs/designs/vanguard.md` (normative canon) · Code: `vanguard/` (cmd/vanguard + internal/{hashnorm,pathmatch,scope,duration,config,docmodel,lockfile,provider,check})

## vanguard.md

- 🔴 **Blocker — `--from <ref>` is never resolved to a commit.** Design (*Check command surface*, `check --from` row): "refs resolve in the target repository and an annotated tag is **peeled to its commit**"; "an unresolvable ref is a usage error with the hint". `internal/check/check.go` `checkRange` passes `sel.From` straight to `Provider.Attribution`, and `internal/provider/provider.go` `Attribution` only uses `from` in the literal string compare `if from != "" && h.String() == from` (line ~372). A ref name such as `v1.2` never equals a commit hash, so the walk never stops at the base commit and walks to the repository root; `resolveRef` is called only for `to` (line ~434). Unresolvable `--from` refs are also never validated.

- 🔴 **Blocker — a document stale solely by `review_after` never sets exit bit 2.** Design (*Output contract*, exit-bit table): bit `2` = "stale detected". `internal/check/check.go` sets `BitStale` only on `d.DocumentChanged || containsString(d.TriggeredWatches, "paths")` (lines 74, 296, 333 — identical pattern in `checkAll`, `checkDoc`, `checkPath`); `review_after` is appended to `TriggeredWatches` but never checked. CUJ 3's glossary reports `status: "stale"` with `exit_bits: 0`.

- 🔴 **Blocker — the entire structure-verification phase is absent.** Design (D9, *Structure schemas*, *Document model*, M2.4–2.5): `internal/format` with markdown (goldmark + closed rule vocabulary), json/yaml (JSON Schema 2020-12 via `santhosh-tekuri/jsonschema/v6`), dsl opacity; `schema:` keying; engine-field stripping before user validation; `links.forbid_broken`; violations `{rule, file, line, message}` from AST nodes. No `internal/format` package exists; no goldmark/jsonschema import anywhere; `Doc.Schema` is parsed and never used; `checkAll`'s own comment admits "schema enforcement is phase-1 for later milestones". `violations[]` is only ever produced by a lock-entry `observed_at` parse failure.

- 🔴 **Blocker — git-mode "scope-empty at observe" guard is dead code.** Design (*Edge-case resolutions*, "Watch glob matches zero files at check time"): "at `observe` time, a watch glob matching zero files is a fatal config error". `internal/check/observe.go` `attest` compares `scopeHash == emptyScopeHash` where `emptyScopeHash = ""`, but `scope.Combine` (internal/scope/scope.go) always returns `"sha256:..."` when `pairs` is non-empty — and observe only calls `ScopeHash` when `len(doc.PathGlobs) > 0`, so the guard can never fire; zero-match globs are attested. (HashProvider mode's `len(snap) == 0` guard works.)

- 🔴 **Blocker — normalized dirty detection is not implemented; production uses the status path.** Design (*Dirty detection and blob reads*, D17, M0 decision matrix, M1.6): dirty = "files whose stat differs from the index are candidates; confirmed by comparing worktree bytes (over the Hash normalization pipeline) against the HEAD blob"; the matrix's "GO — direct path" makes 0.4's normalized comparison production code; "a blobless clone that lacks the blob … reported dirty with the hint". `internal/provider/provider.go` `GitProvider.Dirty` uses only `Worktree.Status()`; `hashnorm` is never invoked for dirty detection; there is no stat-mismatch candidate logic, no HEAD-blob comparison, and no missing-blob "dirty-loud + hint" branch.

- 🟠 **Major — `check <doc>` path-fallback precedence missing.** Design (*Store layout*, "Resolving `check <doc-id or file>` — precedence fixed"): after id lookup fails, the argument is a path resolved against the store dir then cwd, must resolve into `docs/`, with the hint *"documents live under `.vanguard/docs/` — pass the doc id or a `docs/` path"*. `internal/check/check.go` `checkDoc` does only `docByID` and errors otherwise; no path resolution exists.

- 🟠 **Major — `--max-recovery-walk` is parsed then discarded.** Design (*Check command surface*): the flag bounds the first-parent recovery walk (default 1000). `cmd/vanguard/main.go` declares the flag then discards it (`_ = maxRecovery`, line 160); `check.Options.MaxRecoveryWalk` and `Selection.MaxRecoveryWalk` are never populated, and `Engine.recoveryBound()` (check.go) hardcodes `return 1000`.

- 🟠 **Major — `pending` binding notation never emitted.** Design (*Tests bindings*): "`vanguard check` (default) never executes anything; referenced bindings are reported as `bindings: [{name, status: "pending"}]`". `check.ApplyBindings` (which would populate `Bindings`) is only invoked under `--run-bindings` (main.go line 142); `Engine.BindingsFor` (bindings.go) — the only producer of `pending` — is never called anywhere in production code. Default checks show no `bindings[]` at all.

- 🟠 **Major — observe `refused[]` never serialized.** Design (*The observe envelope*): `refused[]` with `{doc, reason, offending}` per refusal kind. `Refused` struct exists (envelope.go) and `Result.Refusals` is populated (observe.go line 63), but `Envelope` has no `refused` field and `renderText` never prints refusals — refusals are invisible in every output format.

- 🟠 **Major — `--prune` reports dropped ids via `hints[]`, not `pruned[]`.** Design (*observe envelope*): "`--prune` reports dropped ids in a `pruned[]` list when `changed` is true". `observe.go` `prune` appends `"pruned %q"` strings to `env.Hints`.

- 🟠 **Major — `anchor_orphaned` never set on the fresh fallback path.** Design (*Anchor resolution — three paths*): recovery exhausted → "compare the scope tree hash at HEAD directly: **equal → FRESH + informational `anchor_orphaned`** (hint: rebase onto the current main, then re-run observe)". `check.go` `gitPathsAxis` returns fresh early when `current == entry.ScopeTreeHash` without setting `AnchorOrphaned`; the flag is only set in the stale/differs branch. The rebase hint string appears nowhere.

- 🟠 **Major — `introducing_commits[]` ordering is lexicographic, not chronological.** Design (*Output contract*): "sorted **oldest → newest** … equal-position ties break by OID lexicographically". `provider.Attribution` sorts commits lexicographically with the comment "oldest→newest refinement happens at the engine layer" (provider.go line ~444) — the engine never performs it.

- 🟠 **Major — check-side future-`observed_at` integrity guard missing.** Design (*Edge-case resolutions*, clock source row): "`observed_at` more than the configured `clock_skew_tolerance` … in the future of `--now` is an integrity violation — the document reports **fatal**… the guard applies only to documents in the result set". `clock_skew_tolerance` is loaded and defaulted (config.go) but consumed only by `observe.attest`; `check` never compares `entry.ObservedAt` against `e.Now` + tolerance.

- 🟠 **Major — store-inside-watch-scope validation absent.** Design (*Anchoring*, "three construction points" + relocation constraint): "config validation **fails fatal** whenever the store directory lies inside the glob's directory at any depth (including a repository-wide `paths: ["**"]` watch on a non-root store)"; also "a document watching its own store directory is a configuration smell the discovery validator flags as a warning". No such validation exists in `config.go`, `docmodel.go`, or `engine.go`. The enumeration-strategy store filter and repository-wide name filter are implemented, but the subtree-strategy precondition (validation) is not — a relocated/deep store silently re-creates the self-referential cycle the design forbids.

- 🟠 **Major — `check --path` classifies the argument by `os.Stat`, not by shape.** Design (*The `check --path` decision procedure*): "a **decision procedure on glob shape** … deliberately independent of what currently exists on disk". `main.go` `resolvePathArg` calls `os.Stat` and sets `PathIsDir` from the result; a not-yet-existing directory argument is treated as a file and direct-matched, contradicting test vector semantics (`--path src/payments` must match `src/payments/api/**` even while `api/` is empty — and even while `src/payments` itself is absent).

- 🟠 **Major — relative `--path` arguments are not checked for `..` segments.** Design (`check --path` row): "`..` segments are rejected (same rule as discovery globs)". `main.go` `resolvePathArg` applies `filepath.IsLocal` only to absolute arguments; a relative `../outside` passes through `filepath.Clean` untouched.

- 🟠 **Major — provisioning entirely missing (no `install`).** Design (D3, *Tool provisioning*, M5.2): command surface is `check` + `observe` + `init` + **`install`**; pinned `url`+`sha256` declarations in `vanguard.yaml`; download-verify-place into `.vanguard/bin/`; `Provisioner` seam; NFR "plaintext HTTP refusal, checksum mismatch fatal". `main.go` registers only `init`, `check`, `observe`; `config.Config` has no tool/provisioning section; nothing reads `.vanguard/bin/`.

- 🟠 **Major — binding execution contract gaps.** Design (*Binding execution contract* table): (a) single-string `cmd: "go test ..."` shorthand **must** be split by POSIX shlex rules — `config.Decode` instead rejects it (`cmd must be a non-empty array`); (b) binary resolution PATH = `.vanguard/bin/` first with execution-time sha256 verification — absent (bindinings resolve via ambient PATH only); (c) timeout kills the **process tree** (process group/Job Object) — `RunBindings` uses `exec.CommandContext`, which kills only the direct child; (d) the optional `output_parser` diagnostic adapter attribute — absent from `rawBinding`/`Binding`.

- 🟠 **Major — provenance line uses the wrong repository's HEAD.** Design (*bindings trust model*): "bindings from vanguard.yaml @ <HEAD short sha of the **repository that contains the store**> (<n> commands)". `bindings.go` `ProvenanceLine` uses `e.Prov.HEAD()` — the *target's* HEAD; for a decoupled store it reports the target commit and never reports the store repo's revision (and `no-git` fires based on the target, not the store).

- 🟠 **Major — unresolved binding references are silent on default check.** Design (*Document model*): engine-owned checks include "watch/binding reference resolution". `BindingsFor` flags unresolved names, but it is never called without `--run-bindings`; a document referencing an undeclared binding passes silently unless bindings are executed.

- 🟠 **Major — discovery warnings are computed then dropped.** Design (*Store layout*, discovery details; G8): "Every skip and every discovery warning carries file + reason". `docmodel.Discover` returns warnings, `Engine` stores them (`engine.go` line 82) — and nothing ever renders them: no envelope field, no text output, nowhere.

- 🟠 **Major — `unobserved[]` store-level array is not sorted.** Design (*Output contract*): "`documents[]` is sorted by `doc` id bytes; **so are the store-level arrays `unwatched[]` and `unobserved[]`**". `checkAll` sorts `env.Unwatched` (line 81) but never sorts `env.Unobserved` (it inherits discovery/RelPath order).

- 🟠 **Major — unwatched documents are appended to `documents[]` with an empty status.** Design (*Output contract*): "`unwatched` appears only in the store-level section (not a per-document status)". `checkAll` appends `Document{Doc: id, Status: ""}` to `env.Documents` for every unwatched doc; the JSON therefore carries status-less document entries outside the closed value set (`fresh|stale|dirty|unobserved`).

- 🟠 **Major — output/presentation contract unimplemented.** Design (*Output formats and terminal presentation*): `--no-color` flag, TTY detection, `NO_COLOR`, lipgloss styling, status colors/alignment, UTF-8/ASCII degradation contract. None exist: no `--no-color` flag in main.go, no lipgloss dependency, `renderText` is plain unstyled text. Go-dependency table lists `github.com/charmbracelet/lipgloss` — absent from the module.

- 🟠 **Major — YAML shape-parity quoting rule not implemented.** Design (*Output contract*): "every string that YAML 1.1 could *not* resolve as a string … is **double-quoted**" (closed quoting rule). `render.go` uses bare `yaml.Marshal(env)` with no quoting rule and no JSON↔YAML parity test.

- 🟠 **Major — DSL `watches` engine field is silently dropped.** Design (*Document model*, format table + DSL block spec): engine fields are `id`, `schema`, `watches`, `bindings` for every format. `docmodel.parseDSLBlock` counts `watches` as an engine key (`isEngineKey`), but `assignField` has no `case "watches"` — a DSL document's watches are swallowed without error, so a DSL doc can never declare `paths`/`review_after`.

- 🟠 **Major — store relocation configuration missing.** Design (D2, G7, store layout): "Documents, configuration, schemas, and the state lockfile live in `.vanguard/` … **The directory can be relocated outside the repository via configuration**". `main.go` `findStore` hardcodes `.vanguard` discovered from cwd; `config.Config` has no store-location key. (Only `target.path` — the *watched* side — is configurable.)

- 🟠 **Major — fatal conditions produce no envelope.** Design (*Output contract*): "a fatal condition is not a status: it sets the exit bit and surfaces through `violations[]`/`hints[]` while per-document statuses stay well-formed" — i.e. the envelope is still emitted. `main.go` returns `engine.Load`/`Check` errors up through cobra (`os.Exit(1)`) with no envelope, no `exit_bits: 1`, no hints payload.

- 🟡 **Nit — `lock` field serialized in every check-mode envelope.** Design shows `lock` only in the observe envelope. `Envelope.Lock` (`LockReport`, no `omitempty`) is marshaled as `"lock": {"changed": false, "path": ""}` in `all`/`doc`/`path`/`range` output.

- 🟡 **Nit — `--run-bindings` silently ignored in range mode.** Design (*Check command surface*, `--strict` row principle): "A flag inapplicable to the selected mode is a usage error (fatal, G8 hint), never silently ignored". `main.go` line 142: `if runBindings && mode != check.ModeRange` — in range mode the flag is silently dropped instead of rejected (only the `--strict`+`--from` case is rejected).

- 🟡 **Nit — observe lacks `--output <file>`.** Design lists `--output <file>` ("write the result to a file instead of stdout") as a surface flag for every mode; only `check` has it (main.go observeCmd registers `--all/--prune/--at/--format` only).

- 🟡 **Nit — observe envelope missing the per-document "commit the lock" hint.** Design observe example: `"hints": ["commit the lock: git add .vanguard/vanguard.lock && git commit"]` per attested document; `observe.go` writes `Document{Doc, ObservedAt, Anchor}` with no hints.

- 🟡 **Nit — observe does not note detached HEAD.** Design (*Edge-case resolutions*, HEAD row): "Detached HEAD: allowed … the report notes *'HEAD detached — anchor describes this commit, re-attest on the intended branch'*". No detached-HEAD detection or note anywhere.

- 🟡 **Nit — observe does not refuse mid-merge/mid-rebase.** Design same row: "Merge/rebase in progress: `observe` refuses with hint *'finalize the merge/rebase, then observe'*". No merge-state check in `attest`.

- 🟡 **Nit — scope-emptied precise hint missing at check time.** Design (*scope_file_count* + edge table): stale-on-empty hint "*scope emptied: 14 files → 0 — the code this document was responsible for moved or vanished*", made precise by the stored `scope_file_count`. `check.go` emits the generic "inspect the commits…" hint; `scope_file_count` is stored but never read by check.

- 🟡 **Nit — DSL leading-block termination is looser than specified.** Design: "the **leading comment block** is the maximal run of consecutive lines each starting with `//` or `#`; the block ends at the first line matching neither". `parseDSLBlock` treats blank lines and `#!` lines *anywhere before the block* as non-terminating (`continue`), so fields after a blank line inside the "leading" block are still extracted.

- 🟡 **Nit — `check --path` includes dirty-only matches.** Design (`check --path` row): "Returns matching documents that are **stale or `unobserved`**". `checkPath` includes any non-fresh status, so a `dirty`-only document is also returned.

- 🟡 **Nit — `observe --all` sweep includes unwatched documents.** Design: "`--all` … attests **only documents currently in the `unobserved` section**". `observe.go` selects every doc with no lock entry, which includes unwatched docs (no watches declared) that belong to the `unwatched` category, not `unobserved`.

## Milestone coverage

- **M0** — partially implemented: `internal/hashnorm` exists as production code (task 0.4 promotion), but no go/no-go memo/matrix artifacts are present in the repo, and the normalized dirty-detection "direct path" outcome was not carried into production — `GitProvider.Dirty` uses the go-git status path the matrix treats as fallback/mitigation.
- **M1** — partially implemented: `pathmatch` (expand → normalize → classify → match → `CouldClaim`), `scope` (entry hash, multi-glob combine, kind prefixes `tree:`/`sha256:`, repository-wide name filter, enumeration store filter), streaming `hashnorm`, GitProvider (subtree OID, enumeration, recovery walk, ref resolve + tag peeling, first-parent merge attribution) and HashProvider all exist with tests; missing: production normalized dirty detection (1.6), store-inside-scope fatal validation, chronological commit ordering.
- **M2** — partially implemented: discovery engine (lexicographic order, symlink skip, unknown-format skip, duplicate-id fatal, id grammar, 256 KiB frontmatter cap, BOM strip, strict YAML with anchors/aliases/merge rejection) and `vanguard init` (scaffold + `{"version": 1, "docs": {}}` + bootstrap guidance) exist; missing: `internal/format` entirely (goldmark rule vocabulary, JSON Schema 2020-12, engine-field stripping, `forbid_broken` link resolution, `max_depth` 32 cap), i.e. the whole structure-verification layer.
- **M3** — implemented (core): canonical sorted serialization with unknown-field preservation, atomic temp+rename CAS write with "lock changed during observe — re-run" abort, observe preconditions with per-kind refusal bits (fatal 1 / dirty 4), future-time guard + monotonicity + `--at`, guarded `--all`, standalone `--prune`, lost-lock detector (all-mode, `lock_lost` + default stale bit, emptied-lock not treated as lost). Drift: `refused[]`/`pruned[]` never reach the envelope, git-mode empty-scope refusal is dead code.
- **M4** — partially implemented: all four check modes, envelope `schema: 1`, exit bits 1/2/4/8/16/32 composed by OR, `--strict`∘`--from` usage error, `--fail-on-affected` bit 32, `--to` defaults to HEAD, net-state rule with recovery walk and `anchor_recovered`/`anchor_orphaned` flags; drift: `--from` unresolved (blocker), review_after-only staleness sets no bit 2, `unobserved[]` unsorted, `anchor_orphaned` missing on the fresh fallback, `--max-recovery-walk` dead flag, no YAML quoting parity, fatal produces no envelope.
- **M5** — partially implemented: bindings allowlist (array form only), direct argv exec (no shell), `cwd: target|store`, `VANGUARD_TARGET`/`VANGUARD_DOC`/`VANGUARD_STORE` injection, per-binding timeout, provenance line, exit bit 16, transient results (nothing persisted); missing: `vanguard install` + pinned provisioning (5.2), `.vanguard/bin/` PATH prepend + execution-time checksum verification, process-tree kill, pending notation on default check, shlex single-string shorthand, `output_parser`.
